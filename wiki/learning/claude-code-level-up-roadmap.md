# Claude Code レベルアップ・ロードマップ

Navigation: [[learning/_index]] | [[index]] | [[hot]]

**対象**: バイブコーディングではなく実務利用(知識管理・介護施設業務・文書作成・調査)が中心の使い方を、段階的にレベルアップさせる12週間計画。

**設計方針**:
- 各レベルは約2週間。**卒業条件を満たしてから次へ進む**(飛ばさない)
- 毎週金曜に振り返り(このページ下部の振り返りログに追記)
- 新しい機能は必ず**実際の業務タスクで試す**(素振りだけで終わらせない)
- Claude Code本体だけでなく、**スキル・プラグイン・MCP・外部リソース**を各レベルで1つずつ取り込む(巻末の[リソース集](#リソース集外部サイトスキルプラグイン)参照)

**用語の整理**(混同しやすいので最初に):

| 仕組み | 何ができるか | 置き場所 |
|--------|-------------|----------|
| **スラッシュコマンド** | 定型プロンプトを `/名前` で呼ぶ | `.claude/commands/*.md` |
| **スキル** | 手順書+スクリプト+参照資料のセット。Claudeが必要時に自動で読む | `~/.claude/skills/` または `.claude/skills/` |
| **プラグイン** | コマンド・スキル・エージェント・フック・MCPをまとめて配布する箱 | `/plugin` でマーケットプレイスから導入 |
| **MCPサーバー** | 外部サービス(Gmail、Notion等)への接続口 | `claude mcp add` で登録 |

このVault自体が「claude-obsidianプラグイン」(スキル+コマンド+フックの詰め合わせ)なので、手元に完成品の見本が常にある。

## Level 0: 現状診断(最初の週末にやる)

まず「今の自分」を記録する。12週間後の比較対象になる。

- [ ] 直近2週間でClaude Codeに頼んだことを10個書き出す
- [ ] それぞれ「何往復かかったか」「やり直しがあったか」をメモ
- [ ] 「毎回同じ説明をしていること」を3つ挙げる → これがLevel 1〜2の材料
- [ ] 「手作業でやっていてClaude Codeに任せていないこと」を3つ挙げる → これがLevel 3〜4の材料

**診断メモ**(記入欄):

> ここに書く

## Level 1: 基礎の底上げ — 指示の質と会話の管理(第1〜2週)

**目標**: 1回の指示で意図が伝わる率を上げる。長い会話で迷子にならない。

### 学ぶこと
- **CLAUDE.md の育て方**: 「毎回同じ説明をしていること」をCLAUDE.mdに移す。`#` を打つとその場でメモリに追記できる
- **プランモード**: 大きめの依頼は Shift+Tab でプランモードに切り替え、実行前に計画を確認してから進める
- **コンテキスト管理**: `/clear`(仕切り直し)と `/compact`(要約して継続)の使い分け。話題が変わったら `/clear` が基本
- **ファイル参照**: `@ファイル名` で対象を明示する。「あのファイル」と言わない
- **中断と修正**: Escで止めて軌道修正する。間違った方向に走らせたまま待たない

### 実務での練習課題
1. Level 0で挙げた「毎回同じ説明」3つをCLAUDE.mdに追記する
2. 次のingest作業をプランモードで開始し、計画を確認してから実行させる
3. 1つの会話で2つ以上の話題を扱ったら、意識的に `/clear` してから次に進む

### スキル・プラグイン・外部サイト
- 公式ドキュメントの「よくあるワークフロー」「メモリ管理」を通読: https://code.claude.com/docs
- Anthropic公式のベストプラクティス記事(実務利用の考え方の土台): https://www.anthropic.com/engineering/claude-code-best-practices
- Anthropic Academy の無料コース「Claude Code in Action」で基礎を体系的に: https://www.anthropic.com/learn

### 卒業条件
- CLAUDE.mdを3回以上更新した
- 「やり直し」の回数が体感で減った

### 振り返り質問(第2週金曜)
- 一発で通った指示と、何往復もした指示の違いは何だったか?
- CLAUDE.mdに書いたのに無視されたことはあるか?(→ 書き方を短く命令形に)

## Level 2: 繰り返し作業の型化 — 自作スキル/コマンド(第3〜4週)

**目標**: 週に2回以上やっている作業を、1コマンドで呼び出せるようにする。

### 学ぶこと
- **カスタムスラッシュコマンド**: `.claude/commands/` にMarkdownを置くだけで `/コマンド名` が生える。`$ARGUMENTS` で引数を受け取れる
- **スキルの構造**: すでに入れたテンダーヒルズ3スキル(care-user-info-excel / admission-script / admission-assessment)の中身を読んで、構造を理解する
- **既存スキルの改造**: 使ってみて「ここが惜しい」と思った箇所をSKILL.mdを直して修正する

### 実務での練習課題
1. テンダーヒルズ3スキルを実際の業務データで1回ずつ使い、改善点をメモする
2. 自分の定型業務を1つ選んで自作コマンドにする(例: `/議事録 [メモ]` → 施設の会議メモを決まった書式に整形、`/週報` → log.mdから今週分を要約)
3. このWikiの `/wiki-ingest` の出力で気に入らない点があれば、スキル側を直す

### スキル・プラグイン・外部サイト
- **Anthropic公式スキル集**(docx / xlsx / pptx / pdf 操作スキルなど。介護業務のExcel・書類仕事に直結): https://github.com/anthropics/skills — Excel帳票を扱うなら `xlsx` スキルをまず入れる
- スキルの仕様と作り方は公式ドキュメントの「Agent Skills」ページを参照
- 手本として、このVaultの `skills/wiki-ingest/SKILL.md` と自分で入れたテンダーヒルズスキルを読み比べる

### 卒業条件
- 自作コマンド/スキルを2つ以上作り、実務で使った
- 既存スキルを1箇所以上自分で修正した

### 振り返り質問(第4週金曜)
- 型化した作業は何分短縮されたか?
- 「型化するほどでもない」と判断した作業は何か? その判断基準は?

## Level 3: 外部サービス連携 — MCPで業務システムとつなぐ(第5〜6週)

**目標**: Claude Codeを「ファイルの中だけ」から出し、メール・カレンダー・ドライブと連携させる。

### 学ぶこと
- **MCPサーバーの追加**: `claude mcp add` で接続。まずGmail・Googleカレンダー・Googleドライブの3つ
- **Obsidian MCP**(任意): `skills/wiki/references/mcp-setup.md` の手順でVaultを直接読み書きできるようにする
- **安全な使い方**: 読み取りは自由に、送信・作成は必ず下書き確認してから

### 実務での練習課題
1. 「今週の未返信メールを要約して、返信の下書きを作って」を試す
2. 「来週の予定を確認して、空いている面談枠を3つ提案して」を試す
3. ドライブ上の書類(入所関係書類など)を読ませて、Wikiにingestする流れを1回通す

### スキル・プラグイン・外部サイト
- **MCP公式サイト**(プロトコルの全体像を30分だけ): https://modelcontextprotocol.io
- **公式リファレンスサーバー集**(何が接続できるかのカタログとして眺める): https://github.com/modelcontextprotocol/servers
- Obsidian MCPのセットアップ手順はVault内にあり: `skills/wiki/references/mcp-setup.md`
- Gmail / Googleカレンダー / Google Drive / Notion はClaude公式のコネクタから接続できる(claude.ai の設定 → コネクタ、またはClaude Codeの `/mcp`)

### 卒業条件
- MCP経由の作業を週3回以上、自然に使うようになった
- 「Claudeに聞く」だけで済んだ調べ物が1つ以上あった(自分でメール・カレンダーを開かずに)

### 振り返り質問(第6週金曜)
- 連携して一番効いたのはどのサービスか?
- 誤送信・誤操作につながりそうな場面はあったか?(→ 権限設定を見直す)

## Level 4: 自動化 — 人がいなくても回る仕組み(第7〜8週)

**目標**: 「自分が指示しなくても定期的に走る」タスクを1つ以上持つ。

### 学ぶこと
- **フック(hooks)**: このVaultにはすでにauto-commitフックがある。`hooks/` の中身を読んで仕組みを理解し、1つ自作する(例: ingest完了時に通知)
- **ヘッドレスモード**: `claude -p "指示"` でターミナルから一発実行。シェルスクリプトやcronに組み込める
- **定期実行**: wiki-lintの定期実行(隔週)、hot.mdの鮮度チェックなどをcron + ヘッドレスで自動化

### 実務での練習課題
1. `claude -p` で「wiki/log.md の直近1週間を3行に要約」を実行してみる
2. 隔週で `/wiki-lint` を自動実行するスクリプトを書く(hot.mdの「lint残課題」を潰す運用に)
3. 業務で「毎週やる確認作業」を1つ選び、ヘッドレス実行のスクリプトにする

### スキル・プラグイン・外部サイト
- 公式ドキュメントの「Hooks」「Headless mode (`claude -p`)」ページが一次情報
- 見本はこのVaultの `hooks/` フォルダ(auto-commitフックの実物)
- 通知系の小物は自作より既存プラグインを先に探す(下記リソース集のマーケットプレイス参照)

### 卒業条件
- 定期実行されるタスクが1つ以上動いている
- フックを1つ自作した

### 振り返り質問(第8週金曜)
- 自動化したタスクの結果を自分はちゃんと見ているか?(見ない自動化は削除する)
- 自動化して初めて気づいた問題はあるか?

## Level 5: 並列化と委任 — サブエージェント/ワーカー活用(第9〜10週)

**目標**: 「1つずつ順番に」から「同時に複数」へ。Claude Code = オペレーター体制を完成させる。

### 学ぶこと
- **サブエージェント**: 調査系のタスクを「サブエージェントで調べて」と明示的に委任する。本体の会話コンテキストを汚さずに済む
- **カスタムエージェント**: `.claude/agents/` に役割特化エージェントを定義(例: 「介護記録レビュアー」「Wiki整合性チェッカー」)
- **Codexワーカーとの役割分担の深化**: すでに確立した [[Codex Worker Pattern]] を、どのタスクをどちらに振るかの判断基準として言語化する

### 実務での練習課題
1. `/autoresearch` で業務関連トピック(介護報酬改定など)を1本走らせ、裏で別作業をする
2. カスタムエージェントを1つ定義して使う
3. 「Claude Codeに向くタスク / Codexに向くタスク / 人がやるべきタスク」の振り分け表をWikiに書く

### スキル・プラグイン・外部サイト
- 公式ドキュメントの「Subagents」ページ(`.claude/agents/` の書式)
- **Codex Plugin for Claude Code**(調査済みのやつを実戦投入する): `/plugin marketplace add openai/codex-plugin-cc` → `/codex:review` などが使える
- コミュニティのエージェント定義例を漁るなら awesome-claude-code(下記リソース集)

### 卒業条件
- 並列で2つ以上のタスクを走らせた経験が3回以上
- 振り分け表がWikiにある

### 振り返り質問(第10週金曜)
- 並列化して速くなったか、それとも確認コストで相殺されたか?
- 委任した結果を信頼できたか? できなかったならどこを直すか?

## Level 6: 運用の仕組み化 — 続く形にする(第11〜12週)

**目標**: レベルアップを「イベント」から「日常」にする。

### 学ぶこと
- **権限設定の整理**: 毎回許可を求められるコマンドを `settings.json` の許可リストに移す(`/fewer-permission-prompts` 相当の整理)
- **Wikiの健全性運用**: lint隔週実行の定着、hot.mdの残課題(North Star / Annual Goals記入、概念ページ作成)の消化
- **自分用プラグイン化**: Level 2〜5で作ったコマンド・スキル・エージェントを1つのプラグインにまとめ、他のマシン/プロジェクトでも使えるようにする

### 実務での練習課題
1. Level 0の診断メモと現在を比較し、差分をWikiノートにまとめる
2. 自作物をプラグインとして整理する
3. 次の12週間の「Level 7以降」を自分で設計する(候補: Agent SDK、チームでの共有、音声入力連携)

### スキル・プラグイン・外部サイト
- 公式ドキュメントの「Plugins」「Plugin marketplaces」ページ(自作物の配布形式)
- 見本はこのVaultの `.claude-plugin/` フォルダ(claude-obsidianプラグイン自体のマニフェスト)
- 自作プラグインをGitHubに置けば `/plugin marketplace add 自分のユーザー名/リポジトリ名` で他マシンにも入る

### 卒業条件
- Level 0との比較レポートがWikiにある
- 「次に伸ばすこと」を自分の言葉で書けた
