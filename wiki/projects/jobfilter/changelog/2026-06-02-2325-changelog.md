## Files Changed

### 1. `app/api/intake/score/route.ts` — Intake engine pipeline fix (CORE)

**What was broken:**
- `username` received in POST body but never read
- WhatsApp trigger hardcoded to `{ triggered: false, provider: 'none' }`
- No Supabase persistence — leads lived only in customer's localStorage
- Tradesperson never notified of incoming GOLD leads

**What was implemented:**
- Capture `username` from request body and include in lead object
- Import `supabase` from `server/lib/supabase` and persist to `intake_submissions` table (graceful no-op if table doesn't exist yet — exits silently on `42P01 table not found`)
- Import `triggerGoldLeadWhatsApp` from `server/services/sms` and call it for GOLD leads (graceful no-op if `WHATSAPP_PHONE_NUMBER_ID`/`WHATSAPP_ACCESS_TOKEN` env vars absent)
- Add `qualityLabel` and `recommendedAction` fields to the returned lead object so `LeadDetailPage` renders them correctly
- Use more unique lead ID format: `intake-{timestamp}-{random4}` to reduce collision risk
- All external calls wrapped in try-catch — API never returns 500 due to missing env vars

**Lines changed:** 66 lines added, 16 removed

### 2. `src/pages/LeadListPage.tsx` — Score threshold alignment

**What was broken:**
- Gold tab threshold: `score >= 90` — but scorer marks GOLD at `score >= 80`
- Silver tab threshold: `score >= 75` — but scorer marks SILVER at `score >= 50`
- A GOLD lead scored at 80–89 appeared in the SILVER tab — users missed their best leads

**What was implemented:**
- Replace raw score comparisons with a `qualityLabel → tier → score` fallback chain
- Priority: `qualityLabel` (set by full scanner), then `tier` (set by intake scorer), then raw score with correct 80/50 thresholds
- Bronze: everything not gold/silver, or explicitly ignored

**Lines changed:** 3 lines replaced with 6

---

### 3. `src/pages/LeadDetailPage.tsx` — Budget flag display fix

**What was broken:**
- `flags.includes('Budget')` displayed as "Budget confirmed — not fishing for a free quote"
- But `Budget` flag is added by the scorer for LOW/suspect budgets (e.g., "cheap" in text, or "Under £500" selected)
- `GoodBudget` flag (added for £500+ budgets) was never displayed at all

**What was implemented:**
- `GoodBudget` flag → "Budget confirmed — not fishing for a free quote" (positive)
- `Budget` flag → "Budget may be tight — qualify before committing a full day" (warning, in orange)

**Lines changed:** 1 line replaced with 2

### 4. `src/pages/IntakePage.tsx` — Customer-facing copy

**What was broken:**
- Customer arriving at `/intake/[username]` saw only "JOBFILTER FOR tradesman" — no explanation of what they're submitting or what happens next
- A confused customer doesn't trust the form and abandons

**What was implemented:**
- Replaced `"JOBFILTER FOR {username}"` label with `"GET A QUOTE FROM {username formatted}"`
- Added sub-headline: "Answer 3 quick questions. Your request is scored for urgency and value — {name} gets a notification so they can respond fast."

**Lines changed:** 1 line replaced with 5
