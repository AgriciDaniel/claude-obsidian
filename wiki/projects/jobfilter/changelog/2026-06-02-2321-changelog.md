## Files Changed (7 files, +77 / -18)

### 1. `app/api/intake/score/route.ts` (+62 lines)

**What changed:** Complete rewrite of the intake scoring Next.js route from a stub to a full implementation.

**Before:** Scored the lead, returned a simple object, always returned `whatsapp: { triggered: false, provider: 'none' }`. No Supabase persistence. No WhatsApp notification.

**After:**
- Imports and calls `persistLeads()` from `server/services/leadPersistence.ts` — saves lead to Supabase on every intake submission
- Imports and calls `triggerGoldLeadWhatsApp()` from `server/services/sms.ts` — fires WhatsApp notification for GOLD-tier leads
- Builds a proper `Lead` object (matching `leadEngine/types.ts` interface) for persistence
- Maps `tier` to `qualityLabel` using valid values ('GOLD'|'SILVER'|'BRONZE')
- Passes `username` from form body through to `signalStack` for tradesman attribution
- Both persistence and WhatsApp calls wrapped in `.catch()` — submission never fails due to missing env vars
- Returns `qualityLabel` and `recommendedAction` in the response so `LeadDetailPage` can display them

**Why:** The Next.js App Router route shadows the Express route. The Express route (with full features) was dead code. The stub meant leads were never saved and tradespeople were never notified.

### 2. `server/services/decisionScoring.ts` (1 line)

**What changed:** Line 60: `'BIN'` → `'BRONZE'`

**Before:** `const tier = finalScore >= 80 ? 'GOLD' : finalScore >= 50 ? 'SILVER' : 'BIN';`
**After:**  `const tier = finalScore >= 80 ? 'GOLD' : finalScore >= 50 ? 'SILVER' : 'BRONZE';`

**Why:** 'BIN' is not a valid quality label in the type system. `Lead.qualityLabel` accepts 'GOLD'|'SILVER'|'BRONZE'|'CHECK'|'SKIP'. The Express route mapped 'BIN' to 'CHECK' via a conditional; the Next.js route was passing 'BIN' directly into the response causing a type mismatch.

### 3. `server/routes/intakeScore.ts` (1 line)

**What changed:** Expanded JOB_TYPES set from 4 to 9 job types.

**Before:** `new Set(['Electrical', 'Plumbing', 'Roofing', 'Building'])`
**After:**  `new Set(['Electrical', 'Plumbing', 'Roofing', 'Building', 'HVAC', 'Carpentry', 'Landscaping', 'Painting', 'Heat Pumps'])`

**Why:** The UI `IntakePage.tsx` shows 9 job types. The Express route would throw a validation error for 5 of them. Though the Express route is currently dead (shadowed by the Next.js route), this should be consistent for correctness and future use.

### 6. `src/pages/LeadDetailPage.tsx` (+2 / -1 lines)

**What changed:** Fixed flag display logic.

- Changed `lead.flags.includes('Budget')` to `lead.flags.includes('GoodBudget')` for positive budget message
- Added display for `Risk` flag: "LOW — ask for a site visit before quoting"

**Why:** The `Budget` flag is set for BOTH low-budget leads ('Under £500', cheap keywords) and indirectly for any budget. The `GoodBudget` flag is the correct signal for "budget confirmed, worth quoting." The `Risk` flag (set when details < 20 chars) was being ignored and not shown to the tradesman.

### 7. `src/components/TopNav.tsx` (2 changes)

**What changed:**
- Subtitle at 2xl breakpoint: "Construction Intelligence" → "UK Trade Leads"
- Nav link order: Moved "Pricing" to position 3 (before "Trades") for conversion; moved "Signals" to position 5 (after Trades, where it makes more contextual sense)

"Signals" as position 3 in the nav confused visitors who don't know what it means — placing "Pricing" earlier captures higher-intent visitors earlier.
