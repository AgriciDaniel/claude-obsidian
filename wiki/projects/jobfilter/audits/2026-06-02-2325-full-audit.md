## INTAKE ENGINE ROOT CAUSE DIAGNOSIS

**Symptom reported by founder:** "The INTAKE ENGINE does not work properly."

**Root cause — 4 compounding issues:**

### Issue 1: Username silently discarded (CRITICAL)

File: `app/api/intake/score/route.ts:12`

The `IntakePage.tsx` sends `{ jobType, urgency, details, postcode, phone, budget, hasPhotos, username }` to the API. The Next.js route receives the body but **never reads `username`**. The lead has no tradesperson association — there is no way to route it to the correct tradesperson account.

```typescript
// BEFORE (broken):
const body = await request.json().catch(() => ({}));
// username not captured — tradesperson never identified
```

### Issue 2: WhatsApp trigger missing from Next.js route (CRITICAL)

File: `app/api/intake/score/route.ts:23–25`

The old Express server (`server/routes/intakeScore.ts`) calls `triggerGoldLeadWhatsApp()` for GOLD leads. The Next.js route that actually runs simply hardcodes:
```typescript
whatsapp: { triggered: false, provider: 'none' },
```
GOLD intake leads **never trigger a WhatsApp notification** to the tradesperson. This is the reason the flow "doesn't work" — the tradesperson gets no alert.

### Issue 3: No server-side persistence (CRITICAL)

File: `app/api/intake/score/route.ts` — no Supabase call

The Express server calls `persistLeads([lead])`. The Next.js route doesn't. Submitted leads exist only in the **customer's** localStorage (via `saveStoredLead` on the frontend). The tradesperson has no server-side view of submitted intake leads.

### Issue 4: Score threshold mismatch in LeadListPage (HIGH)

File: `src/pages/LeadListPage.tsx:78–80`

The scorer (`decisionScoring.ts`) uses `score >= 80 → GOLD`, `score >= 50 → SILVER`. But the lead list tabs used `score >= 90 → GOLD`, `score >= 75 → SILVER`. A GOLD lead scored at 80–89 appeared in the SILVER tab.

### Fix applied this run:
- Issues 1, 2, 3: Fixed in `app/api/intake/score/route.ts` — username captured, Supabase persistence added (graceful no-op if table absent), WhatsApp trigger wired up (graceful no-op if env vars absent).
- Issue 4: Fixed in `LeadListPage.tsx` — thresholds now use `qualityLabel` → `tier` → `score` fallback chain with correct 80/50 thresholds.

### What the founder still needs to do:
1. Create Supabase table `intake_submissions` (DDL in STICKY-TODO.md)
2. Set `WHATSAPP_PHONE_NUMBER_ID` + `WHATSAPP_ACCESS_TOKEN` env vars
3. Set `SUPABASE_SERVICE_ROLE_KEY` env var for server-side DB writes
